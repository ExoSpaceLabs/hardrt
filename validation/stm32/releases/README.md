# Release qualification packages

`validation/stm32/releases/` is an optional **local retention area** for one selected physical qualification package per release, for example:

```text
validation/stm32/releases/v0.5.0/
validation/stm32/releases/v0.6.0/
```

These directories are gitignored. Do **not** commit generated hardware evidence after qualification, because doing so would change the source SHA that was physically tested.

For a release:

1. run `scripts/stm32_manual_test_full.sh` unfiltered on the frozen source SHA;
2. inspect the complete passing report and raw logs;
3. optionally retain the selected package here locally;
4. publish the selected archive as a GitHub Release asset from the tag that points to that exact qualified source commit.

Do not retain ad-hoc failed or partial runs as release packages. Development evidence belongs under the timestamped `validation/stm32/<UTC>_<short-sha>/` locations generated by the runner.
